# 给老板报 1.x 进度的口径（助理 2026-11-19 写，给 grokbot 和各岗照做）

老板要的是一眼看懂：一句结论 + 一张短清单。照下面四步做。

## 1. 先定分母，框架和插件分开
- 总量基准：四部分合计 447–697 人天 = 框架 283–429 + SandIAM 125–191 + SandAI（乙类）39–77（来源 `review-1117-r3/顶层架构设计-v4.md:678–682`）。workflow 没有独立盘子。
- 框架 283–429 里嵌着插件归属行，要扣掉才是“框架核心”：业务插件连带改造 129.05–159.5（SandAI、SandWorkflow、SandLicense 前后端，v4 L567–573）+ AI 流式 2–4 + AI 超时 0.5–1 + AI 安全 1–2 + install.sql 转 MySQL 0.8–2，合计约 133–169。
- 框架核心 ≈ 150–260 人天。报“框架核心”时用这个分母；报“整个框架”时用 283–429。永远不合成“框架+插件”总完成率。

## 2. 分子只算已验收的
- 只算“已合并 + 有同范围独立验收证据”的活，按 v4 f1 和 11-17 独立审计新增表的行折算人天（部分完成按比例，写依据）。
- 不算：方案写完、只跑出 rc0、源码改完未独立验收、未合并的 PR；不按 PR 数估；限定检查计数（如 PASS 7 FAIL 0）不能包装成百分比。
- 同一成果不重复计；归属按“归谁算谁”：分子里属于插件归属行的（如 PR #92 流式基础层 1.5–3 归 SandAI A3）要从框架核心分子里扣掉。
- 找不到同范围映射的写“待核算”并写明缺什么，不编数字。
- 2026-11-19 结果：框架核心已验收约 13.8–27.5 人天，完成约 9%–11%，剩约 136–233 人天；整个框架约 5%–7%；SandIAM、SandAI 0%（技术总监已复核）。

## 3. 报“一批任务占多少”时
- 把任务分成两类：对应框架 f1/审计表行的“工作量项”，和规范、审计、拆解、归档、队列等“保障项”（保障项不算框架人天）。
- 工作量项逐项写对应行的人天区间，加总，再除以框架核心分母和整个框架分母，下限对下限、上限对上限。
- 例（2026-11-19 队列 17 项）：工作量项 7 个合计 14.3–27.7 人天 → 占框架核心约 10%、整个框架 5%–6%；其余 10 项是保障项。并注明“只有合并并验收后才计入完成度”。

## 4. 对老板的写法
- 第一句就是结论数字（“约占框架核心 10%”）。
- 下面一行一项：名字加粗 + 人天区间，最大的那块点明。
- 最后一句说口径和前提（谁复核过、合并验收后才算）。不堆过程。

## 5. 给老板列“还没排的活 / 计划”时（老板 2026-11-19 要求以后都这么列）
- 第一句点明卡进度的是哪一类、为什么（例：“框架核心剩下的人天大部分要建库才能做”）。
- 分三类，每类写项数和人天合计：
  一、无库、下一批就排：一行一项，名字加粗 + 人天区间 + 前置条件（要等哪个 PR 合并、排在谁之后），PR 写完整链接。
  二、要建库或迁移的（大头）：按主题归组（鉴权、数据库底座、业务能力），只写组名和代表项，不逐条。
  三、等拍板的：直接点名几件事。
- 最后一段写“我的计划”：第一类怎么滚动排、第二类怎么解锁（例：排本地 Fusion 审计，通过视为放行，隔离库开做），不问老板，写成要做的事。
- 数字来源：核心拆解报告（results/1b-core-breakdown-1119/RESULT.md）里各行的人天区间，下限加下限、上限加上限。
