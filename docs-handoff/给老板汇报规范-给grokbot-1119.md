# 给老板汇报的规范（助理 2026-11-19 写，给 grokbot 和各岗照做）

老板是读结论、做决定的人，不是改代码的工程师。她要一眼看懂：成没成、占多少、要不要她做事、下一步是什么。

## 一、六条规矩
1. **结论放第一句。** 成了、没成、卡在哪，第一句就说。
   - 改前：“已按任务读 HANDOFF 与只读包索引，hash 核对通过（0e12a08…），继续核对……最终 7/7 PASS。”
   - 改后：“插件卸载修复做完了，测试复跑全部通过，还没合并。”
2. **不用内部代号。** WP8、J-14、B15、M-05、哈希、行号、提交号、文件路径，一律换成它说的那件事。
   - 改前：“B14 的 Origin 部分与 N3 合并成 2-G。”
   - 改后：“HTTP 安全中间件（响应头、来源校验、跨域白名单）。”
3. **数字带分母。** 不说“做了 12 项”“PASS 7”，要说占多少、还剩多少（分母和算法见《进度汇报口径-给grokbot-1119.md》）。
   - 改前：“已验收 12 项映射。”
   - 改后：“框架核心完成约 9% 到 11%，还剩约 136 到 233 人天。”
4. **一行一项。** 三件以上的事用列表，每行：名字加粗 + 一句话 + 数字或前置条件。PR 写完整链接，一个 PR 一行。
5. **说跟她有什么关系。** 要她做决定的，单独一句写清选项和你的建议；不需要她做事的，就不要问。
6. **结尾写下一步。** 一句话：接下来做什么、什么时候有结果。不写“如有问题请告知”。

## 二、篇幅
- 日常汇报一到三句；她问“列一下”时才列清单。
- 过程、证据、命令输出放进报告文件，消息里只给结论和链接。
- 技术细节她问了再说。

## 三、发出前自查三问
1. 老板读第一句就知道结果吗？
2. 有没有她不认识的词？有就换掉。
3. 她要不要做决定？要的话问清楚了没有，不要的话有没有多问？

## 四、出口
- 团队规矩：各岗位开始、做完、卡住先报助理，由助理统一报老板。grokbot 回来后照此执行，汇报先给助理，助理按本规范改写后再发老板。
