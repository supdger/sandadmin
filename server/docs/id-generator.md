# 雪花发号器与两类主键约定

依据：规格 v4（J-3、总表 17 条）与《编号两列表-修订》（已批准版，2026-11-18 老板批准，
共 210 张表：自增 68 张、雪花 142 张）。逐表归类以该表为准，本文只写规则。

## 位布局

63 位，PHP int64 可放下，对外输出字符串：

| 字段 | 位数 | 说明 |
| --- | --- | --- |
| 毫秒 | 41 | 距自定义纪元 2026-01-01T00:00:00Z（epoch ms 1767225600000）的偏移 |
| 节点 | 13 | 0–8191，按部署分段 |
| 序列 | 9 | 每进程每毫秒 512 个，溢出等下一毫秒 |

实现：`Sandadmin\Infra\Id\SnowflakeGenerator`；进程级共享实例由
`IdGeneratorGuard` 启动自检后挂到 `SnowflakeRuntime`，业务侧通过
`SnowflakeRuntime::generator()` 或注入取同一个实例。序列只在单实例内
连续，**禁止各处自建实例**——同一毫秒都会从 0 重排发出重复号。

## 节点号与号段

配置 `config/idgen.php`，三项均必填、缺失或非法时启动自检拒绝启动：

| 配置键 | 环境变量 | 说明 |
| --- | --- | --- |
| `idgen.node_range` | `SAND_IDGEN_NODE_RANGE` | 本部署分到的号段，闭区间，格式 `"起始-结束"` |
| `idgen.node_id` | `SAND_IDGEN_NODE_ID` | 本机发号节点号，必须落在号段内 |
| `idgen.max_clock_backwards_ms` | `SAND_IDGEN_MAX_CLOCK_BACKWARDS_MS` | 回拨拒发阈值（毫秒，正整数） |

号段存在的意义是防拿错配置：节点号不在号段内即拒启。**同一号段内不同
发号进程必须各拿不同的节点号**；webman 单配置多 worker 时各 worker 共用
同一 `node_id`，需要按进程细分节点号的部署形态是剩余待决项（见末节）。

## 时钟回拨

回拨量小于 `max_clock_backwards_ms`：阻塞等待时钟追上后继续发号；
达到阈值：拒绝发号（`ClockBackwardsException`）并向 default 日志通道告警。

阈值默认值**待技术总监定**（v4 J-3 待决项），定稿前部署必须显式配置
`SAND_IDGEN_MAX_CLOCK_BACKWARDS_MS`。

## 两类主键

| 类别 | 判定 | 主键 |
| --- | --- | --- |
| 数量可预见 | 人在后台手动维护：部门、岗位、字典等 | int 自增（PG `int GENERATED BY DEFAULT AS IDENTITY` / MySQL `int unsigned AUTO_INCREMENT`） |
| 不可预见持续增长 | 流水、日志、回执、防重记录——跟着每次调用往上涨 | 雪花 64 位 bigint，应用层发号，写入时赋值，不靠数据库 |

补充约定：

- 对外不可猜链接（分享、下载）用 nanoid **单独一列、不当主键**；
- 接口里雪花 id 一律输出字符串，调用侧 `(string)` 转换，防 JS 精度丢失；
- 外键与被指向主键同型；
- 逐表归类以《编号两列表-修订》为准。

写入示例：

```php
$data['id'] = $data['id'] ?? $idGen->next();  // $idGen 为共享的 SnowflakeGenerator
$row['id'] = (string) $row['id'];             // 输出接口字段时转字符串
```

## 本任务不含

- 节点租约表 `sand_system_id_node` 与心跳续期；
- 外键同型的静态检查工具；
- PostgreSQL / MySQL 两库实测；
- 多 worker 节点号细分方案（当前同一机内各 worker 共用 `node_id`）。
