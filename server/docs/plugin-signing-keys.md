# 插件包签名密钥管理规范（PLG-02）

本文是 SandAdmin 1.x 离线插件包签名的密钥管理规范：信任模型、信任根、
私钥保管、轮换、吊销与验签语义。验签实现见
`server/src/Module/Package/PackageSignature.php` 与 `tools/package-ops`，
本文是其中「信任根细则放行稿待定」对应的放行稿。

## 信任模型

- 1.x 插件是完全受信代码，权限等同内核；签名是「包来自受信来源且未被
  篡改」的准入证明，不构成沙箱，不对外暗示有隔离。
- 验签失败一律拒绝：未提供签名、签名文件不可读、公钥缺失或不可读、
  签名与包字节不符，全部按验签失败处理——不解包、零写入。

## 信任根与公钥管理

- 官方发行公钥内嵌进内核发行包，随内核制品一起受签名保护；后台界面
  不提供修改入口。
- 部署方自有签名公钥只能经 CLI 加入本地信任白名单，加入动作记审计
  （操作人、时间、key id、公钥指纹）；不经网页通道加公钥。
- 每把公钥有 key id（kid）；签名侧车文件携带 kid，验签按 kid 选钥，
  多密钥并存。

## 签名格式

- 算法：Ed25519，对插件包 zip 字节整体做分离签名；先验签后解包。
- 目标格式：签名侧车文件为 JSON 信封——
  `{ "kid": "<key id>", "alg": "Ed25519", "sig": "<base64>" }`。
- 过渡格式（当前实现）：签名与公钥各自成文件、内容为原样字节或
  base64，不带 kid；验签公钥由调用方逐次显式提供。

## 私钥保管

- 发布私钥离线保管或放 HSM/云 KMS，保管人由技术总监指定并登记在案。
- CI/构建环境只拿得到签名接口，拿不到私钥本体；每次签名动作双人复核。
- 私钥永不进代码仓库、数据库、日志、Issue 或会话记录；任何环节不出
  私钥明文。

## 轮换

- 新公钥随内核版本下发，新旧公钥并存一段窗口期，窗口内任一受信公钥
  验签通过的包都可安装。
- 旧私钥停用即吊销（进吊销列表），不再产生新签名。
- 轮换的计划、执行人、完成确认全部写审计。

## 吊销

- 吊销列表随内核更新下发，按 kid 生效；验签时 kid 命中吊销列表即拒绝。
- 私钥疑似泄露：立即吊销该 kid、发安全公告、用新密钥重签受影响包；
  疑似泄露的密钥一律作废，不得沿用。

## 验签与安装门禁

- check / install / upgrade 三个动作统一先验签后解包。
- 编译版（生产）宿主整体不执行插件安装与升级；未编译版只有在显式
  `--allow-unsigned` 参数下才放行无签名包——该口子只存在开发/构建
  环境，不进生产。
- 验签结果 `signature_verified` 如实落 journal 与输出：真实验签通过
  才为 true，allow-unsigned 放行记 false。

## 实现现状对照

| 规范条目 | 当前实现 | 差距 |
| --- | --- | --- |
| 先验签后解包、验签失败一律拒绝 | 已实现：Ed25519 分离签名，验签先于 zip 解析，问题清单即拒绝 | 一致 |
| 编译版/生产禁安装、unsigned 口子只留开发 | 已实现：编译闸在验签前整体拒绝；`allowUnsigned` 仅未编译版显式参数 | 一致 |
| 官方公钥内嵌内核发行包 | 未实现：公钥由调用方 `--pubkey` 逐次传入 | 待实现：信任根内嵌 + 本地白名单 |
| 部署方公钥白名单 + 审计 | 未实现 | 待实现 |
| 签名带 kid、多密钥并存 | 未实现：过渡格式无 kid | 待实现：侧车信封格式 |
| 吊销列表随内核更新下发 | 未实现 | 待实现 |
