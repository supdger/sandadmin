# sandadmin1x-ai-loop（AI 开发闭环）

本 skill 写给「在 sandadmin 1.x 项目上干活的 AI」：拿到任务该走什么流程、过哪些门禁、
MCP 能干什么不能干什么。sandadmin 1.x 的核心卖点是面向 AI 开发——项目自己带
AGENTS.md 和 skill 让 AI 上手，框架自己带 MCP 服务让 AI 能查能干，代码改动靠
一条固定的「分支 → 测试 → 检查 → 合并 → 发版」闭环收口。

## 总纲（硬规矩，对应老板 5/6/7/8 条）

- **只在分支改**：所有改动走 feature 分支提 PR，禁止直接改/推 `main`/`master`。
- **每个模块带测试**：新模块、改模块必须带测试一起交付；接口测试从 `openapi.yaml`
  生成，不能只有手写的零散用例。
- **合并前三关全过才许合并**：静态检查、编译检查、测试，缺一不合并。
- **发版保留上一版**：上一版签名制品必须还在、能直接拿出来重新部署回退；
  **生产不执行迁移回退脚本**——回退 = 切上一版制品 + 按需恢复备份，回退脚本
  只用于测试库验证与「刚上线未写数据」窗口的人工确认应急回退。
- **MCP 双向不依赖 SandAI**：框架层自带的 MCP 服务和「调外部 MCP」的能力是内核
  功能，AI 干活不等、不装、不引用 SandAI 插件。
- **免登录只在开发构建**：dev-login 整条链用 `SAND_DEV_BUILD` 编译期常量包裹，
  生产包编译期整段剔除，任何 env/配置都不能在生产把它放回来。

## 接到任务先做的事

1. 读仓库根 `AGENTS.md`（项目自带薄入口）和它指到的本仓 skill，确认本次改动
   落在哪个目录、哪个模块。
2. 判断改动类型，按下表加载对应 reference，不全读：

| 任务碰到什么 | 读哪个文件 |
| --- | --- |
| 用/改 MCP 服务、给 AI 工具开能力、接外部 MCP | `references/mcp.md` |
| 分支、测试、静态检查、编译检查、合并、发版、回退 | `references/delivery-loop.md` |
| 写/改 AGENTS.md、给项目新增自带 skill | `references/project-selfdesc.md` |

3. 后端分层、命名、编号、响应壳等代码写法规矩不在本 skill，按 AGENTS.md
   指的 backend/frontend skill 走；本 skill 只管「流程怎么走、门禁过没过」。

## 合并前门禁清单（速查，全文在 delivery-loop.md）

- [ ] 改动在 feature 分支，PR 已开；鉴权/插件安装/CI 路径改动需 2 人或安全岗审批
- [ ] 模块测试齐备（测试目录缺即门禁失败）；接口测试与路由/权限/MCP/TS 类型
  由 OpenAPI 契约构建期生成，生成物与源一致；PG 和 MySQL 双库都过
- [ ] 涉及迁移时：每份迁移带回退脚本，测试库跑过「升级→回退→再升级」；
  删列删表等丢数据步骤在回退脚本里写明「不可逆，靠升级前备份」；
  恢复点检查通过——**生产不执行回退脚本**
- [ ] PHPStan 最高级别（含仓内自定义规则）+ deptrac + eslint/tsc + 命名自查全过；
  门禁文件改动过人审、基线/豁免只减不增
- [ ] 编译检查过：`SAND_DEV_BUILD` 未定义时 dev 链零残留、`verify=false` 零命中
- [ ] PR 审批齐、状态检查绿；新提交作废旧审批

## 一句话边界

- MCP 对外服务：能查表/菜单/权限/接口，也能执行操作——写操作分三档：只读
  直执、普通写必带幂等键 + `dry_run`、高危写只生成「待确认请求」由人 sudo
  批准；机器身份是机器令牌（`sand_system_api_token`，摘要 + scope + 过期），
  任何 scope 都不能直执高危、不能调批准接口。**同一套权限码、同一套审计**，
  不存在「MCP 通道特权」；生产默认关。
- 调外部 MCP：只许调 `sand_system_mcp_server` 登记的外部 MCP 服务，登记时
  锁工具清单摘要（变了自动停用待复核），凭证走配置/密钥体系，出网走统一
  出网入口，调用记审计。
