# delivery-loop：分支 → 测试 → 检查 → 合并 → 发版 全流程门禁

适用：在 sandadmin 1.x 仓库上做任何代码改动。每一步都有「过/不过」的判定标准，
不允许「差不多过了」。

出处说明：分支保护、供应链门禁、CI 构建出自顶层架构设计-v4 G 节 SCM-01~11
（arch:1378-1388）；测试锚点出自鉴权P0-v4 回归矩阵 R31–R63 与双库 CI 矩阵
（auth:989-1040；arch:1515）；dev 链剔除出自鉴权P0-v4（auth:383-386,958）；
「OpenAPI 生成测试」「只在分支改全过才合并」「迁移带回退脚本」「发版保留
上一版可回退」出自 v4 U-6 / B-25（arch:1996-2006, :66）；门禁挂 GitHub
Actions + 本地合并前必跑脚本出自 v4 T-8 / B-23（arch:1912-1925, :64）。

---

## 第 0 步：开工

- [ ] 读了根 `AGENTS.md`，确认改动落在哪个权威目录（`server/src`=内核权威、
  `server/app`=薄壳、`server/database/migrations/`=宿主迁移、`web/`=唯一前端；
  `server/plugin/` 是 Composer 产物不改）。
- [ ] 从最新主干拉出 feature 分支。**禁止**直接在 `main`/`master`/`release/*` 上
  提交；禁止 force push、禁止删已保护分支。
- [ ] 改动范围只含本任务该动的文件；顺手发现的无关问题另开分支，不夹带。

## 第 1 步：测试（每个模块带测试）

- [ ] **新模块/改模块必须带测试**：交付物 = 代码 + 同模块测试，缺一不算完成。
  「模块」判定口径（M-11）：`server/src/Module/<名>` 或插件包 + 对应测试目录，
  **测试目录缺失即 CI 失败**；改动行覆盖率有阈值（建议 80% 可配，pcov）；
  测试数据用工厂 `server/tests/Factory/`，不手拼夹具；每个菜单页一条
  Playwright 冒烟（打开、列表、新建、保存；S-15），机器冒烟之外**人工真点
  保留为交老板验收前的最后一关**。后端测试类 `<被测类>Test`，方法
  `test<做什么><什么情况>`；前端 `同名.test.ts(x)` 放被测文件旁边
  （命名规范 §四.10/12）。
- [ ] **接口测试从 OpenAPI 生成**（v4 U-6，对照 1）：`openapi.yaml` +
  `api-conventions.md` 是契约权威、唯一来源；权限码、MCP 工具、错误码都挂
  它的扩展字段（`x-permission`/`x-mcp`/`x-error-codes`）。接口改动前先改契约
  文件，**构建期**机械派生：路由表、权限注册表、MCP 工具表、TypeScript 类型、
  接口测试骨架（状态码、字段、权限 401/403 用例）；权限点/路由/MCP 注册表
  不在运行期反射扫描（M-12），启动期只做一致性校验。接口改了 OpenAPI 不改、
  或生成物与源不一致，门禁报错。生成的测试进 PR、进 CI 双库跑。
  生成器归属与产物位置：仓内自带脚本（放 `server/tools/` 或 `scripts/`
  下，不引外部重工具链），产物落仓内测试目录（如 `server/tests/contract/`）；
  TS 类型为构建产物（S-14），未接生成管线前至少挂「类型与契约比对」门禁。
  派生物是构建产物不是代码生成器（不写业务逻辑、不生成控制器/模型/页面）
  【老板 2026-11-17 已定 R-2】。
- [ ] **双库都要跑**：迁移执行器、方言层、涉及 SQL 的模块按「PG 最新 LTS ×
  MySQL 8.0 系末版 + MySQL 8.4 LTS 推荐线（特性所需小版本见 v4 L-1；支持下限
  仍是 8.0+，8.0.x 安装检出给警告不拦安装）」矩阵跑同一套测试；插件迁移
  两库各跑一遍，任一库红即不合并（arch:1515）。
- [ ] **迁移带回退脚本**（v4 U-6）：每份迁移必须带回退脚本，合并前在测试库
  跑过「升级→回退→再升级」；存量历史迁移压成一份基线迁移（S-07，基线本身
  不要求 down）；多实例滚动升级先加后删（expand/contract），「后删」类晚
  一个版本执行；删列删表等丢数据步骤，回退脚本里写明「不可逆，靠升级前
  备份」。**生产环境不执行回退脚本**（M-07）：生产回退只切上一版制品 +
  按需恢复备份，回退脚本只用于测试库验证与「刚上线未写数据」窗口的人工
  确认应急回退（sudo + 审计）。迁移前执行器先做恢复点检查
  （`RecoveryPointProviderInterface`，M-13：小库现场 dump、大库登记快照号/
  PITR 位点经 `--recovery-point` 传入写审计），拿不到可用恢复点拒绝迁移，
  不静默跳过。
- [ ] **驱动类同一套契约测试**：有多种驱动的能力（会话存储 redis/db 等）用同一套
  契约测试跑全部驱动（auth:1040 区域 R58 口径）。
- [ ] **回归矩阵对号入座**：鉴权相关改动对照 R31–R63 逐条确认是否新增/受影响
  用例（登录/锁定/验证码/票据/中间件链/默认路由/找回/会话存储/版本号单调写/
  组织隔离/出网校验/越权矩阵）；命中即补用例进回归。

## 第 2 步：静态检查

- [ ] **PHPStan 最高级别**（老板规矩第 4 条），含仓内自定义规则全过：
  `NoDialectSqlRule`（`ON CONFLICT`/`ON DUPLICATE`/`FOR UPDATE`/`SKIP LOCKED`
  字面量只许出现在 `src/Infra/` 方言文件）、跨组织裸 SQL 检查、
  `org_id IS NULL` 放行分支检查、`org_id` 表检查（arch:1086,1407；auth:227）。
- [ ] **deptrac**：Service 层禁依赖 Connection 等分层规则全过。
- [ ] **前端**：仓库自带 `eslint` + `tsc --noEmit` 全过；`pnpm-lock.yaml` 入库、
  `--frozen-lockfile` 安装。
- [ ] **TypePHP 写法**（老板规矩第 4 条，v4 T-8/B-23）：新代码
  `declare(strict_types=1)`；参数/返回值/局部变量类型标注完整；无魔术方法/
  动态属性/动态调用/变量变量；常驻进程不放全局请求态；业务声明文件顶层不执行
  初始化。
- [ ] **命名自查**：`naming_check.py sql|code --diff|notes --diff|terms` 无
  FAIL；豁免登记 `naming-allow.txt` 一行一条带原因。
- [ ] **供应链**：`composer audit --locked` + `pnpm audit --audit-level=high`
  （或 osv-scanner）High/Critical 阻断；新增直接依赖过 CODEOWNERS 评审；
  gitleaks 秘密扫描零命中。

## 第 3 步：编译/构建检查

- [ ] **dev 链剔除（R43 口径）**：构建产物 grep `DevPrincipal|DevLogin` 及发信桩
  驱动零残留；`SAND_DEV_BUILD` 未定义时 dev 链路由/Provider/桩驱动不挂载不注册。
- [ ] **出网校验（R61 口径）**：生产构建代码里 `verify=false`/
  `CURLOPT_SSL_VERIFYPEER=0`/`VERIFYHOST=0` 静态检查 0 命中。
- [ ] **契约信封形状**：v1 组异常出 `{code,message,fields,request_id}`，非 v1
  不被契约信封覆盖（R34）。
- [ ] **能编译就编译（可选）**：TypePHP 编译目标存在时跑编译检查；无编译目标不
  强制搭环境。

## 第 4 步：合并（PR 门禁，SCM-07 口径）

- [ ] 必走 PR，**≥1 人审批**；改动落在鉴权、插件安装、CI 路径的，**≥2 人或
  安全岗审批**。bot 用独立机器账号，真人审批名单进 CODEOWNERS（S-13）。
- [ ] 新提交作废旧审批——最后一次提交之后必须有有效审批。
- [ ] 状态检查全绿：第 1/2/3 步的检查项挂进仓库现有 GitHub Actions 当合并
  门禁 job（PHPStan 最高级别、命名检查、测试；TypePHP 编译检查作可选 job，
  工具链可用时启用；v4 T-8/B-23），全过才合并。本地 `scripts/` 下配合并前
  必跑脚本，与 CI 同一套命令；分支保护随门禁 job 配置，不旁路。
- [ ] **门禁分快慢两级（R-8）**：PR 跑快门禁（静态检查、命名检查、单元测试、
  生成物一致性、安全回归）；合并队列或夜间跑全矩阵（PG + MySQL 8.0 系末版
  + MySQL 8.4 LTS 三库的契约/迁移/回归），不让每个 PR 等三库。
- [ ] **门禁自保护（M-09/对照 8）**：
  - 门禁文件（PHPStan 基线、deptrac 配置、`naming-allow.txt`、CI workflow、
    安全回归用例目录、门禁脚本 `tools/`）进 CODEOWNERS，改动必须人审，
    AI 提的改动不算自批；
  - 基线、豁免清单**只减不增**——新增豁免须人审并写明到期日，CI 检出
    基线/豁免净增即失败；
  - 删测试、改断言、降 PHPStan 级别的提交打标签必须走人工 review，禁止
    AI 自己批准；
  - 每个门禁输出机器可读报告（JSON/SARIF），「过了」要有证据不是嘴上说。
- [ ] **门禁工具进仓（M-10/对照 9）**：检查脚本进仓库 `tools/`、1.x skill 进
  `.agents/skills/`，随代码版本走；CI 只用仓内版本；上游 `~/.shared-skills`
  是唯一源，仓内是副本、发版前做哈希比对，不一致即失败（R-3）。
- [ ] lockfile 变更过依赖负责人审批；`main`/`release/*` 保护规则不旁路。

## 第 5 步：发版与回退

- [ ] **制品只在 CI 构建**（SCM-11）：tag 触发 GitHub Actions，附 SHA-256 +
  CycloneDX SBOM + Sigstore 来源证明；个人电脑产物一律不发布；容器镜像 cosign
  签名；安装闸验 Ed25519 签名 + 来源证明。
- [ ] **出包前置**：`SAND_DEV_BUILD` 未定义 + dev 链文件整条剔除 + R43 通过 +
  dev-login 与旧路由处置完成；缺一不得出包（auth:958）。
- [ ] **发版保留上一版可回退**（v4 U-6，M-07）：「上一版」= 上一版签名制品
  （构建产物 + SBOM + 来源证明），制品按版本存放、至少保留上一版；发新版前
  确认它仍在制品库、可直接重新部署。新版上线后发现致命问题时的回退动作 =
  **切回上一版制品 + 按需恢复备份**——**生产不执行迁移回退脚本**，本版
  「先加」类迁移保留不回退；回退脚本只在测试库验证与「刚上线未写数据」
  窗口的人工确认应急回退（sudo + 审计）里用（口径见第 1 步迁移条）。发版
  手册与回退演练属运维暂缓（P-8），框架只保证「上一版制品 + 回退脚本在
  测试环境验证过」可用。
- [ ] 发版记录：版本号、制品 SHA-256、来源证明、对应 tag 写入发版记录；
  CHANGELOG 按 Keep a Changelog 更新。

## 证据分级（汇报时照此区分）

每个结论标注一个标签，不混用：**checked**（只读看过）/ **modified**（改了文件）
/ **verified locally**（本地跑过检查）/ **committed**（已提交）/ **merged**
（已合并）/ **deployed**（已部署）。静态检查过 ≠ 测试过 ≠ 运行验证过；
构建成功不是「已上线」。
