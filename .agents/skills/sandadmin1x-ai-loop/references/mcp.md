# mcp：框架层 MCP 双向约定

适用：开发、接入、审查 sandadmin 1.x 的 MCP 能力；或 AI 通过 MCP 在实例上干活。

出处：顶层架构设计-v4 U-3（对外 MCP 服务，2026-11-17 独立审计轮 M-01/M-02/M-03
落实）、U-4（调外部 MCP，S-01/对照 4 工具定义锁定）、U-5（框架层定位，ADR-22）、
N20（机器令牌进 1.0）；生产默认关的上线检查见 T-10 第 5 项；鉴权侧见
鉴权P0-v4 A-18 机器令牌节。

---

## 一、定位（硬规矩）

- MCP 双向是**框架内核能力**，不依赖 SandAI 插件：
  - **对外**：框架自己对外提供 MCP 服务，AI 工具（Claude Code、Devin、IDE 插件
    等）作为 MCP 客户端连进来。
  - **对内**：框架能作为 MCP 客户端调用外部登记的 MCP 服务。
- 不装 SandAI，框架照样能被 AI 查和办、照样能调外部 MCP（U-5）。SandAI 作为
  插件经扩展点往框架 MCP 服务里**注册自己的工具**，权限、审计、令牌全用框架
  这一套；它要调外部 MCP 时用框架的客户端接口，不各自再写一套。
- **框架 MCP 不认 SandIAM 令牌、不认旧 JWT**（M-04/M-01）：只认宿主机器令牌
  与内核会话两种身份；SandAI 经框架 MCP 只注册**平台管理类**工具；知识库、
  对话、提示词等**租户数据类工具一期不经框架 MCP 暴露**——否则平台后台账号
  经 MCP 可跨租户读数据。将来若做「产品用户经 MCP」，另设经 SandIAM 令牌
  认证的产品侧入口（插件内容，复用框架协议层、不复用宿主身份）。
- MCP 不是后门、不是特权通道：MCP 上的每次查询和操作，和后台界面上的同动作
  走**同一套权限码、同一套审计、同一份契约信封**。AI 用 MCP 能做的事 =
  该身份在界面上能做的事，一件不多。
- MCP 能力挂在 v1 契约面下实现（复用 `RequestContext`、权限码判定、审计），
  端点与普通 v1 同一入口、同一 TLS 与限流层，不单起进程、不另写第二本审计账。

## 二、对外 MCP 服务

### 协议与运行形态（M-03，定死）

- 协议锁定**无状态 HTTP 修订版**（MCP Streamable HTTP / 无状态模式，每请求
  自带令牌，不依赖长连接会话）；有状态会话模式一期不做（若将来用，会话存
  `SessionStoreInterface`，不依赖进程内存）。
- 协议栈用官方 `mcp/sdk`（PHP SDK）**锁定版本**包进适配层，不自己拼
  JSON-RPC；SDK 升级走依赖评审。
- 工具**显式登记**：工具清单 = 「工具名 → v1 路由 + 权限码 + 三档分级」，
  **构建期从 OpenAPI 扩展字段 `x-mcp` 生成**（U-6/对照 2），不是运行期扫描、
  不用反射或注解自动发现；没标 `x-mcp` 的接口不暴露为工具，工具清单不能
  手工加东西。
- MCP 请求进**普通 Web 进程组**（不另起进程池）；流式输出复用
  `StreamWriterInterface`；按令牌、按工具分别限流（进全局限流桶）。
- 开发环境本地连接校验 `Origin`、只绑本机回环（127.0.0.1）；开发连接只在
  开发构建存在，生产包编译期剔除。

### 查询类（`x-mcp: read`，只读，按权限码过滤可见性）

| 能力 | 能查到什么 | 权限约束 |
| --- | --- | --- |
| 表结构查询 | 表清单、列、索引、约束、表注释 | 持有对应域读权限码；`sand_system_*` 内核敏感表按权限码分级，不整库裸开 |
| 菜单查询 | 菜单树、路由、菜单-权限绑定 | 只返回调用方权限码可见的子集 |
| 权限查询 | 权限码清单、角色-权限关系、用户角色 | `system:role:read`/`system:user:read` 系列权限码 |
| 接口查询 | OpenAPI 契约、路由清单、错误码总表 | 契约文件本身是仓内公开物，查询不设额外闸 |
| 系统设置查询 | 系统设置项 | 敏感项脱敏后返回 |
| 日志检索 | 日志检索能力 | 按调用方权限码过滤，安全日志只读；**必须走 `SearchInterface`/日志查询接口，不直接拼 SQL**（M-08） |

### 执行类（写操作分三档，M-02 定死）

| 档 | 声明 | 执行方式 |
| --- | --- | --- |
| 只读 | `x-mcp: read` | 直接执行，同 v1 只读接口 |
| 普通写 | `x-mcp: write` | **必须带幂等键**（重复提交同键返回首次结果，不重复执行——防 AI 重试重复执行）；**支持 `dry_run=true`**（只校验并返回将做什么，不落库） |
| 高危写 | `x-mcp: high_risk`（即 N4 清单动作） | **不直接执行**——只生成「待确认请求」（状态机：待确认→已批准/已拒绝/已过期，形状复用 `sand_system_lifecycle_request`），由人在后台过 sudo 批准后才按对应 v1 接口执行，全程审计 |

- 每个执行类工具都对应一个现有 v1 接口和它的权限码，同一套鉴权、同一套
  数据范围、同一套审计；没有对应权限码的动作不允许出现在 MCP 工具清单里——
  **MCP 工具集 ⊆ 接口能力集**。
- **机器令牌一律不能直接执行高危动作**——不管令牌 scope 多大，高危写永远走
  「待确认请求 + 人批准」（已进 E 节不支持清单）。
- **待确认请求的批准规则（安全 M-02，依据 OWASP LLM06，防提示注入生成的
  请求被人顺手批掉）**：
  1. 批准页完整显示该请求的全部参数（不截断、不只显示摘要）；请求生成时
     固定参数摘要（规范化 JSON 的 sha256），批准时记录该摘要，执行时按批准
     那一刻的摘要重算比对，参数有任何变化即作废、须重新生成和批准；
  2. 批准人本人必须持有该动作对应的权限码（与人工直接操作同一权限判定）；
  3. 机器令牌一律不能调用批准/拒绝接口——批准接口只接受人工会话 + sudo，
     Bearer 身份直接 403。
- 执行类工具单独开关 `mcp.write_enabled`（默认关）；只读与执行类分开 scope
  授权，查询类默认可用、同样受权限码约束。
- **生产默认关**，后台显式打开（T-10 上线检查清单第 5 项）；开关变更走
  sudo 再验证、写审计。签发 MCP 写 scope（`write`/`high_risk`）令牌、打开
  网页提交通道、开通生产 MCP 服务这三个动作要求操作账号已绑定 TOTP
  【老板 2026-11-17 已定 R-1】。

### 身份与审计（M-01，机器令牌进 1.0）

- 身份只有两种：浏览器会话（`SessionAuthenticator`）与机器令牌
  （`TokenAuthenticator`）。**不存在第三条免登录/内部令牌路**；旧 tinywan
  JWT 与一切非本表 Bearer 一律 401。
- 开发环境走本地连接（只在开发构建存在，开发身份权限不超过当前开发账号）；
  生产用机器令牌 `sand_system_api_token`（int 自增主键）：
  - 只存 sha256 摘要、明文只在签发时显示一次；
  - scope 白名单、必填过期、记最近使用、关联具体账号 +
    `issued_authz_version` 联动失效；账号停用/删号或 `authz_version`
    变化令牌立即失效；
  - 实际权限 = 该账号权限 ∩ 令牌 scope，scope 只能缩小不能放大、不豁免
    任何权限或数据范围；机器令牌不签发会话、不持有 `sudo_until`；
  - 签发/吊销仅管理面入口，走 sudo 再验证 + 写审计（N4 高危清单含
    「签发机器令牌」「吊销机器令牌」两行）；按令牌限流独立桶。
- 每次 MCP 调用记审计：「身份来源 = MCP + 账号 + 令牌名/令牌号 + 工具名 +
  档位 + 幂等键 + 参数摘要 + 结果」，审计行带**通道标记 `channel='mcp'`**，
  「AI 经 MCP 干的」和「人在界面干的」可分查；进安全日志，留存下限 183 天
  （T-4）。高危写「待确认请求」整条链路（生成→批准/拒绝→执行）都进审计。
- MCP 的读取同样走数据范围规则，写操作同样过授权不越级校验（目标权限集 ⊆
  操作人权限集）；越权 403 + 审计，与界面口径一致。
- 【老板 2026-11-17 已定 R-6】开发期 MCP 最小版（做，1.5–3 人天）：在 U-3 之外给开发构建加一组
  开发专用工具（查路由与契约、看最近错误与慢请求、跑指定测试、跑门禁脚本），
  不做代码生成、只在开发构建存在（`SAND_DEV_BUILD` 编译期整段剔除）、复用
  U-3 服务不另起一套。

## 三、对内：调外部 MCP 服务

- [ ] 外部 MCP 服务在后台登记（表 `sand_system_mcp_server`：名称、地址、传输
  方式、启用状态；int 自增主键）；代码里不许出现未登记的端点。
- [ ] **工具定义锁定（S-01/对照 4）**：登记时拉取并保存该服务的工具清单
  （工具名、参数模式）与内容摘要（哈希）；之后每次连接对比摘要——工具清单
  变了就**自动停用该服务**，等管理员复核后重新登记才恢复，防外部服务偷偷
  加工具或改参数（供应链投毒面）。
- [ ] 调用侧三道闸：**每工具白名单、返回体大小上限、每分钟调用预算**（超
  预算 429 并告警）。
- [ ] 凭据经 N5 加密、进密钥体系，不落库明文、不进日志、不写进仓库；日志
  脱敏器覆盖 MCP 调用记录中的凭证类字段。
- [ ] 出网走统一出网入口：地址校验、内网地址拦截、白名单，强制证书链 +
  主机名校验；超时、重试、熔断按 G 节默认值；生产构建 `verify=false`/
  `VERIFYPEER=0` 零命中（R61 口径同样覆盖 MCP 出网）。
- [ ] 外部 MCP 的返回是**不可信输入**：进业务前过 schema 校验，不直接拼 SQL、
  不直接进模板、不直接当权限判定依据。
- [ ] 对外部 MCP 的每次调用记审计（谁、调了哪个外部服务的哪个工具、结果、
  耗时），响应体与载荷不落全量敏感内容。
- [ ] 插件（含 SandAI）调外部 MCP 一律经框架提供的 MCP 客户端接口，不各自
  再写一套。

## 四、MCP 能干什么 / 不能干什么（速查）

**能干**：
- 查表结构、菜单、权限码、接口契约、系统设置（脱敏）、日志（经查询接口），
  辅助定位「该改哪、权限码叫什么」。
- 执行与令牌背后账号权限码相符的普通管理操作（`mcp.write_enabled` 已开、
  带幂等键；先 `dry_run` 再实执）。
- 对高危动作**发起**待确认请求，由人在后台 sudo 批准后执行。
- 帮验收取证：拉审计行、查迁移账本、核对菜单/权限实际落库状态。

**不能干**：
- 绕过权限码、数据范围、审计的任何「管理员直查/直改」。
- 用机器令牌直接执行高危动作、调用批准/拒绝接口（Bearer 直接 403）。
- 绕过分支-合并-发版闭环：MCP 执行的是**运行实例上的管理操作**，不是往仓库
  写代码；改代码永远走 delivery-loop。
- 用 MCP 通道读写 `sand_system_audit_log`/`sand_system_login_log` 做删改——
  这两张表对任何通道都只有 INSERT + SELECT。
- 在生产用 dev 身份/桩凭据连 MCP——dev 链已随 `SAND_DEV_BUILD` 剔除，生产
  不存在该签发方。
- 把外部 MCP 的返回直接当事实写库或当权限依据。
- 经框架 MCP 提供租户数据类工具（M-04）。

## 五、落 MCP 相关代码时的检查表

- [ ] 新 MCP 工具：在 OpenAPI 上标了 `x-mcp` 档位（read/write/high_risk）？
  对应了哪个现有 v1 接口、绑权限码了吗？构建期工具表生成物一致吗？
- [ ] 普通写工具：幂等键强制了吗？`dry_run` 支持了吗？
- [ ] 高危写工具：只生成待确认请求、没有直接执行路径？批准页全参数 +
  摘要比对、批准人有权限码、Bearer 调批准接口 403，三条都落了吗？
- [ ] 审计行带 `channel='mcp'`、工具名、档位、幂等键、参数摘要了吗？
- [ ] 读类工具返回内容按调用方权限码过滤了吗？日志检索走 `SearchInterface`
  了吗？
- [ ] 外部 MCP 端点在 `sand_system_mcp_server` 里登记了吗？工具清单摘要
  存了吗、变更自动停用复核了吗？白名单/返回体上限/调用预算三道闸在吗？
  凭证经 N5 加密进密钥体系了吗？出网走统一入口了吗？
- [ ] 生产构建里 MCP 面默认关了吗？后台开关的变更过 sudo 再验证并记审计了吗？
- [ ] 测试：查询可见性、越权 403、高危待确认流（机器身份不能直执/不能批准）、
  审计字段，五类用例齐备。
