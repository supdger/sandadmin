# SandAdmin 1.x 插件契约

本 skill 只写**框架对插件的约定**：插件怎么接进内核、必须做什么、禁止做什么、框架保证什么。不写任何具体业务插件的实现内容——框架本身单租户，宿主零业务插件必须能装、能登、能管。

## 先分清你在干什么

| 你在做的事 | 读这份 |
| --- | --- |
| 写插件：目录结构、清单字段、扩展点、表前缀、权限、身份、迁移、生命周期、能力边界 | [references/contract.md](references/contract.md) |
| 发包与装包：zip 内容、catalog、签名、安装通道、供应链门禁、验收证据 | [references/packaging.md](references/packaging.md) |

## 十条最硬的约定（动手前先背下来）

1. **插件是完全受信代码，等同内核**。安全只靠包签名、来源白名单、代码审查三样；框架不提供插件沙箱，文档和对外口径不许暗示有。
2. **插件接入只走内核扩展点**（ExtensionManifest 声明式注册）。清单声明什么宿主挂什么；不许 SQL 插行登记菜单/授权，不许扫目录自动注册。
3. **插件不直写 `sand_system_*` 内核表**。要用的宿主数据走插件 SDK。
4. **插件不自带登录、权限、用户体系**，不自己构造 RequestContext；后台侧身份只认内核会话、权限只认 v1 权限码。
5. **插件不自带安装器、更新器、网页终端**，不经网页上传 zip 获得代码执行。
6. **插件迁移只交声明式迁移文件序列**，由内核执行器统一执行、按连接 + 插件命名空间记账（独立命名连接的插件账记在自己连接的库里）；不再自带 `install.sql`/`update.sql`/`uninstall.sql` 自执行；迁移语句只允许动本插件前缀的表；生产环境不执行回退脚本。
7. **表名前缀 `sand_<插件词干>_*`**，权限码 `<域>:<资源>:<动作>`（域段用插件词干全称含 `sand_` 前缀，如 `sand_foo:record:read`；已定，总监 11-17）；编号规则（可预见表 int 自增、不可预见持续增长表雪花 64 位 bigint、接口输出字符串，nanoid 只作对外不可猜链接单列、不当主键）与时间字段三件套跟宿主同一套规范。
8. **默认要求 PostgreSQL + MySQL 8.0+ 双库**（推荐并测试 MySQL 8.4 LTS；特性小版本差异见 v4 L-1）；只支持一种的在清单 `databases` 字段如实声明，装到不支持的库被安装闸拦截。
9. **插件包必须真实签名**（建议 Ed25519），验签失败一律拒绝；包内必带 lockfile + CycloneDX SBOM，禁止自带 `vendor/`/`node_modules/`。
10. **生产环境插件动作只有查看、启用、停用**；安装/升级只走离线包 + CLI，未编译版另有受限网页申请通道（详见 packaging.md）。

## 老 0.x 契约的作废点（最容易踩的坑）

- `info.ini` 状态机账本、`config.json` 依赖声明、`install.sql`/`update.sql`/`uninstall.sql` 三件套、`host_min` 版本号——全部作废，替代物见两份 references。
- 依赖旧兼容层（sand-core）的基类/中间件/缓存/模型、挂 `CheckLogin`/`CheckAuth` 旧中间件——全部脱钩，走内核会话与 v1 权限码。
- 网页在线拉包安装到生产、网页上传 zip 直接执行包内 PHP/SQL、网页终端、插件私有迁移台账——全部不再支持。

## 汇报口径

每个结论分清：改了什么 / 查了什么 / 本地验证了什么 / 提交了什么 / 装了什么 / 真实安装验收了什么。构建过、包冒烟过、下载校验过，都**不是**安装验收。证据分级见 packaging.md 第 8 节。
