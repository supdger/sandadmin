# 鉴权与安全（后端规矩）

适用范围：登录、会话、权限、审计、安全开关相关的 `server/` 代码。原则：**鉴权只有一条链、一个身份源**，任何旁路都算安全漏洞。

## 一、身份取用（所有代码适用）

- 取当前身份一律走 `IdentityProvider`/`RequestContext`：**禁止**自己解析 Cookie/令牌、**禁止**信任客户端传来的身份字段（`check_admin`、uid 头等自带值一律丢弃，由服务端注入）。
- 超管判定统一 `sand_system_user.is_super` 布尔列；**禁止** `id === 1` 之类字面特判。
- 审计、日志里的 `actor` 一律取 `RequestContext` 会话身份，不从参数取。
- 权限判定只认 v1 权限码 `<域>:<资源>:<动作>`（如 `system:user:read`）；控制器动作用 `#[Permission(...)]` 声明，不手写"查库看角色"的散兵游勇逻辑。

## 二、登录与会话链（改这条链先读完 v4 鉴权稿）

固定流程，不得旁路：

1. `GET /auth/captcha` 签发点选验证码 → `POST /auth/captcha/verify` 原子核销（对错皆废）签发一次性 `login_ticket` → `POST /auth/login` 在密码校验**之前**用独立短事务消费票据（对错皆作废）。客户端传的 `verified` 字段不可信。
2. 密码 Argon2id 校验在锁外做；验证-签发两段协议：事务内 `FOR UPDATE` 重核 hash/version/status 一致才发会话。
3. 会话 = 服务端不透明令牌 + `Set-Cookie`（`HttpOnly; Secure; SameSite=Lax`），响应体永不带 token；绝对有效期 12 小时（可调上限 ≤24 小时）+ 空闲超时同时生效——空闲分档：普通账号 ≤120 分钟可调，管理员和高权限固定 30 分钟不可调。
4. 凭据事件（改密/重置/停用/删除/角色变更）同事务 `authz_version + 1` + 条件吊销旧会话；读会话必校验 `authz_version`，吊销不留复活口。
5. 失败计数三维度（`account_ip`/`account`/`ip`）固定窗口原子计数；锁定只锁组合不锁其他来源；IP 维度永不硬锁。
6. 客户端 IP 只经 `ClientIpResolver` 取（只信 `security.trusted_proxies` CIDR，`Forwarded` 优先于 `X-Forwarded-For`，从右往左剥可信段）；**禁止**用 `getRealIp()` 做计数/审计/登录日志；全系统只有这一套代理白名单，不许另设第二套。

## 三、RBAC 与数据范围

- RBAC 五件套归内核：用户、角色、权限码、菜单、部门（+岗位、字典）；权限码就是唯一判定凭据，**禁止**另搞"角色 id 硬编码"判定。
- 授权不越级（保存前必查）：分配角色/改角色权限/改用户时，目标权限集 ⊆ 操作人权限集，且目标用户权限不高于操作人；`is_super` 只有超管能授予且走 sudo 再验证；越权返 403 + 写审计。部门维度复用"本部门及下级"判定。
- 数据范围：返回他人数据的接口必须在受限路由表登记范围规则（本人/部门及下级/持权限码）；`data_scope` 查询侧未实现前，普通账号默认不放行；新增接口漏登记 = CI 门禁失败。
- 高危操作走 sudo 再验证清单（改超管、角色权限变更、插件启停卸载删除、全量导出、安全设置、系统更新、**签发机器令牌、吊销机器令牌**、代人重置双因素、改联系方式、解除锁定等）：校验 `sudo_until_time` 窗口（10 分钟；已定，总监 11-17），绑会话，轮换/吊销即失效；有 MFA 的账号优先走 MFA；窗口外调高危接口返回契约错误码（`SUDO_REQUIRED`；已定，总监 11-17），前端按码弹窗。

### 3.1 机器令牌（Bearer 服务账号，M-01）

- 生产环境 MCP 服务、服务账号、自动化调用的机器身份通道。1.0 只有两种身份：浏览器会话（SessionAuthenticator）与机器令牌（TokenAuthenticator）；**不存在第三条免登录/内部令牌路**；旧 tinywan JWT 与一切非本表 Bearer 一律 401。
- `sand_system_api_token` 表（int 自增主键）：只存 sha256 摘要、明文只显示一次、scope 白名单、必填过期、记最近使用、关联具体账号 + `issued_authz_version` 联动失效；账号停用/删号或 `authz_version` 变化令牌立即失效。
- 实际权限 = 关联账号权限 ∩ 令牌 scope，scope 只能缩小不能放大、不豁免任何数据范围；机器令牌不签发会话、不持有 `sudo_until`。
- 签发/吊销仅管理面入口，走 sudo 再验证 + 写审计；按令牌限流独立桶；审计记「身份来源 = MCP/服务账号 + 账号 + 令牌名/令牌号」三元组。
- 【老板 2026-11-17 已定 R-1】**签发 MCP 写 scope（`write`/`high_risk`）令牌、打开网页提交通道、开通生产 MCP 服务**这三个动作，要求操作账号已绑定 TOTP。

### 3.2 MCP 高危写与待确认请求（M-02）

- MCP 执行类工具分三档：只读直执；普通写必带幂等键 + 支持 `dry_run`；**高危写（N4 清单动作）不直接执行**——对机器身份只生成「待确认请求」（状态机：待确认→已批准/已拒绝/已过期，形状复用 `sand_system_lifecycle_request`），由人在后台过 sudo 后批准才按对应 v1 接口执行；机器令牌任何 scope 都不能直执高危。
- 待确认请求批准规则（依据 OWASP LLM06，防提示注入生成的请求被顺手批掉）：①批准页完整显示全部参数（不截断），生成时固定参数摘要（规范化 JSON 的 sha256），执行时按批准那一刻的摘要重算比对，变了即作废重批；②批准人本人必须持有该动作对应的权限码；③批准/拒绝接口只认人工会话 + sudo，机器令牌 Bearer 直接 403。

## 四、安全开关（后台可配，默认值写死）

| 开关 | 默认 | 规矩 |
| --- | --- | --- |
| TOTP 双因素 | **关** | 1.0 实装（绑定 otpauth:// 扫码、校验、恢复码、解绑/代人重置全套，开关只是控谁被要求绑定）；平台后台第二因子**只用** TOTP 或恢复码，短信不作第二因子、只用于找回密码；恢复码只显示一次、只存摘要、一次性、用后强制重绑；配置项建议名 `security.mfa.enabled`，打开后可设「全站要求绑定」或「按角色要求绑定」，变更走 sudo + 写审计；**要过等保三级的部署必须打开**，安装引导、安全设置页、上线检查清单写明；产品用户的双因素归 SandIAM，不在内核 |
| 密码定期更换 | **关** | 后台开关；弱密码检查常开（最小 12 位、禁与当前同、弱密码表命中拒绝） |
| 安全日志留存 | ≥183 天 | 安全日志 = 登录、操作、审计日志 + 找回密码与双因素事件 + 权限变更；配置键建议名 `log.retention.security_days`（默认 183、最小 183），低于下限启动报错、设置页不让保存；改动留存期走 sudo + 写审计 |
| 普通日志留存 | 可配 | 普通日志 = 运行日志、任务运行记录、调试类；配置键建议名 `log.retention.normal_days`（默认 183、最小 30）；清理按类执行、按月分区整月删 |
| dev-login（开发免登录） | 仅开发构建 | 整条链用 `SAND_DEV_BUILD` 编译期常量包裹挂载点；发布构建整段剔除、产物 grep 零残留；生产启动检测到桩驱动/免登录组件即拒启；环境变量不是防线 |

## 五、审计与日志

- 两张安全日志表：`sand_system_audit_log`（操作）、`sand_system_login_log`（登录）；应用运行账号对它们只有 **INSERT + SELECT**，清理用独立账号，界面/API 无删改入口。
- `sand_system_audit_log` 1.0 只预留 `changes` 列（字段级改前改后历史），实装 1.1。
- 写面只留 `sand_system_audit_log`；旧 `sand_system_oper_log` 属旧面随退役，过渡期只读不写新行、历史数据不迁移并表（已定，总监 11-17）。
- 操作日志沿用响应后落库模式（先出响应再异步落库）；但失败计数、验证码消耗、失败审计各自走独立短事务，先提交再返回业务失败信封。
- 日志统一脱敏器（字段黑名单 + 正则脱敏令牌/手机号/身份证/口令）；结构化 JSON 并转义 CR/LF 防日志注入。
- **禁止**进日志的东西：密码、Cookie、`login_ticket`、验证码答案、找回令牌、短信验证码、`SAND_CRYPTO_KEY` 等一切密钥材料。
- 密钥管理：主密钥 `SAND_CRYPTO_KEY` 只进 env，不落库不进日志；密文格式 `v<keyver>:<nonce>:<ct>:<tag>`（AES-256-GCM）；旧密钥 `SAND_CRYPTO_PREVIOUS_KEYS` 按 keyver 轮换尝试。

## 六、中间件链生产守卫

- worker 启动遍历全部路由断言：无 `CheckLogin`/`CheckAuth` 旧中间件残留、受保护路由持旧 JWT 返回 401、`id===1` 旁路不存在；断言不过**拒绝启动**；插件安装/升级后必重跑。
- 安全响应头统一中间件输出（见 backend-structure.md §五）。
- CSV/Excel 导出统一走防公式注入转义函数（`= + - @`、Tab/CR/LF 前置 `'`），所有导出口强制过同一个函数。
- 存储/缓存故障口径：鉴权相关（会话、权限版本、限流、验证码）一律 fail-closed；普通缓存可回源放行。会话存储故障返 503 + `Retry-After`，不返 401。

## 七、写代码时容易犯的错（逐条自查）

- [ ] 没自己解析令牌/Cookie，身份从 `IdentityProvider` 取？
- [ ] 新接口进了对应路由表（公开/must_change/受限），返回他人数据的登记了范围规则？
- [ ] 写操作在 v1 组内过 CSRF→Error→Auth 链，权限码已登记？
- [ ] 高危操作进 sudo 清单而不是自己弹判断？
- [ ] 日志没带密码/令牌/验证码答案，`actor` 取自 `RequestContext`？
- [ ] 改的不是 dev-login 链路；如果动了它，确认剔除面还完整？
- [ ] 涉及登录/权限/会话/审计的改动，测试覆盖了允许和拒绝两条路径？
