## Context

远程 main 64661e4 已锁定 Core 0.2.0 / SandPackage 0.2.1。当前工作区有历史未提交抽离，不作为发布来源；独立克隆远程主线。现有 frontend publisher 已支持校验旧清单并安全发布。

## Goals / Non-Goals

**Goals:** 使源码下载无需等到安装完成才得到当前基础包管理前端，明确宿主组合和维护者更新入口。

**Non-Goals:** 修改基础包实现、消费宿主同步、数据库初始化/迁移、后台真实更新事务与共享服务启停。

## Decisions

- 通过标准 Composer 钩子取得受管载荷，不手工放宽保护；保留未受管宿主文件。比较新增文件、两清单与包源码。
- Core 配置的 app.version 属于基础包当前契约，不在宿主额外维护平行版本源；宿主 0.2.0 在 README/CHANGELOG 声明组合版本。
- Core/Package 维护方修复发布后主动交接版本、固定源码引用、变更、兼容范围与验证结果；宿主维护者跟进依赖约束、锁文件及 Composer 发布载荷，组合验收后发布。测试和部署宿主最后同步并核对实际加载版本。沿用现有协作交接，不新增通知服务或定时拉取配置。
- 详细文档沿用现有 Wiki；本轮只准备受影响页面草稿，不推送 Wiki。

## Risks / Trade-offs

- [前端发布冲突] → 运行真实 composer install；不删清单绕过保护。
- [提供方版本已发布但宿主未跟进] → 提供方主动交接明确版本及验证结果，宿主核对实际依赖与载荷，验收组合后发布。
- [数据库与Windows证据不足] → 显式记录未验证范围，不将macOS安装/构建称为完整业务验收。

## Migration Plan

发布固定的 0.2.0 源码组合；消费宿主自行选择明确版本并保留配置与数据库备份。出现问题退回先前源码、锁文件和构建产物；本轮没有数据库变更。
