# SandAdmin 1.x 框架介绍与定案（2026-11-19，老板确认）

用途：交接给 grokbot 和各岗位；可直接整理成官网介绍或框架文档。来源：老板 2026-11-19 20:41 原话“4项按你建议来……全部都计入交接文档”，以及助理当天给老板的介绍。

## 一、一句话定位（目标表述）

SandAdmin 1.x 是基于 workerman 常驻内存的 PHP 高性能企业后台框架。它以 Go 和 Java 一流框架为标准，在安全、稳定和性能上用压测数字、故障演练和安全审计说话，而不是只跟 PHP 框架比。

使用条件：这句话现在只作为设计目标。对外使用前必须过四道关（高标准清单无空项、本地 Opus 安全稳定专项审计问题全补、真实库集成+压测+故障演练通过、安全岗按清单复查），并把下面三类证据的数字填上。

证据（每类都要有数字和报告）：
1. 性能：单机每秒请求数、P99 延迟、AI 流式同时在线路数，附压测报告。
2. 稳定：进程崩溃 3 秒内自动拉起、发版不停服零失败请求、数据库故障切换时间。
3. 安全：通过威胁建模和独立安全审计；插件签名、权限和数据权限全部有自动化测试守住。

对标对象：Go 的 Gin、go-zero、Kratos；Java 的 Spring Boot、Spring Cloud、Vert.x、Quarkus。PHP 的 FPM 框架只当底线。

## 二、1.0 功能

1. 登录与账号：登录、改密、双因素、找回密码、登录锁定、会话管理。
2. 权限：用户、角色、菜单、按钮权限，加数据权限（只看本部门、本人的数据）。
3. 插件体系：插件安装、升级、卸载、签名校验；插件和框架用同一套前后端写法。
4. 数据库：PostgreSQL 和 MySQL 两种库，统一连接、主从读写分离、迁移和回滚、全局编号。
5. 常用业务能力：字典、通知、审计日志、表格导入导出、分段上传（本机和对象存储）、附件分类。
6. 后台任务：任务队列（重试、延迟、失败补偿）、定时任务、任务中心页面。
7. 安全：密钥和字段加密、HTTP 安全防护、限流、出网防护、插件供应链校验。
8. 稳定和性能：健康检查、崩溃自动拉起、不停服发版、连接复用、压测达标。
9. 可观测：结构化日志、请求追踪编号、指标接口、慢查询记录。
10. AI 能力：SandAI 内置，AI 流式输出，MCP 工具让 AI 按权限调用框架功能。
11. 前端：React 加 Semi Design 的管理后台界面（前端任务先用官方 Semi MCP）。

## 三、1.1 功能

1. 更高并发：协程和 PHP 原生异步，等官方稳定后接入；1.0 已按可替换接口设计，业务代码不改。
2. 全链路追踪和告警平台。
3. 配置中心和动态刷新，改配置不用重启。
4. 灰度发布，按用户或比例放量。
5. 跨地域备份和恢复，加系统化故障演练。
6. 更强的队列：Redis Streams 队列、任务链、实时进度推送、独立消息队列和分布式事务。
7. 审计日志防篡改哈希链、CDN 签名地址。

## 四、老板 2026-11-19 定案（原“待拍板”四项，按助理建议）

1. 国际化：1.0 所有界面文字走语言包，只出中文包；其他语言等客户需要再加，加时不改代码。老板补充：尽量参考业界传统、通用做法（如常见的语言包键值文件加回退语言），别搞太复杂。
2. 工作流归属：做成插件，不进框架核心。框架只提供事件、任务队列和扩展接口。
3. MySQL 最低版本：8.4 LTS（MySQL 8.0 已于 2026-04 停止官方支持）。PostgreSQL 保持 15 以上。此条取代总表里“MySQL 8.0+”的旧口径。
4. 双因素范围：后台管理员账号必须开，用手机验证器（TOTP）加恢复码，不用短信；普通后台账号默认关，管理员可按角色强制开；改超管、改权限、卸载插件、全量导出等高危操作一律再验证（与 11-17 定稿的 R-1 一致）。

老板同时定：后台开发阶段要免登录（只限开发环境，生产包不得带免登录入口，发版自检要拦）。其他细节由团队自定。
